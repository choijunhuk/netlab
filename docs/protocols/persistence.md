# Project persistence and examples

JSON schema version 1 stores configuration only. Unknown fields, including runtime caches, leases, NAT mappings, trace records and scheduler callbacks, are stripped. Validation constructs a new object and never changes the input; callers replace their active document only after import succeeds. Import/export enforce a 2 MiB UTF-8 limit, at most 100 devices and 200 links, finite numbers, bounded services, globally unique IDs/MACs, existing unoccupied ports, and loop-free Layer 2 domains. Link-down and powered-off state do not hide structural cycles. Switch ports are one Layer 2 domain; routers keep their ports separate. Duplicate IPs are allowed across isolated Layer 2 domains.

An unconfigured interface is editable: IP/prefix may both be absent, as may its gateway. Configured IPv4 addresses reject network/broadcast host addresses for prefixes below /31. A /31 represents a two-address point-to-point subnet with both addresses usable. A /32 represents one endpoint host route and cannot have a different on-link default gateway; use a connected route on another interface to reach other hosts. Route destinations must be canonical network addresses. Configured next hops must be usable addresses on the selected interface subnet, distinct from its own address. DHCP is bounded to 254 addresses per pool and requires a static server interface in that subnet.

IndexedDB database `netlab-projects`, store `documents`, key `autosave` contains validated JSON, never runtime state. Writes resolve only after transaction completion. Unavailable/blocked storage, transaction failures and invalid saved JSON reject with errors so the UI can offer JSON export. No silent in-memory fallback claims a save succeeded.

The six stable example IDs are `same-lan`, `router`, `two-routers`, `dhcp`, `dns-web`, and `nat`. Their IDs and local-admin unicast MACs are deterministic fixtures. Newly created devices reserve unused IDs/MACs against all existing devices; duplication copies kind and service ports but clears addressing, routes, DHCP, DNS records and NAT configuration to avoid stale references and address conflicts. Links are document-level and are not duplicated. Routers have four ports and switches have eight.
